## Запись 1 (ЛР №9 — Взаимодействие 1: Генерация набора тест-кейсов по требованиям)
- **Дата и задача:** 09.11.2026. Составление базового набора ручных тест-кейсов (позитивные, негативные, граничные, интеграционные, API) для системы учёта заявок.
- **Модель:** Gemini (Google AI), веб-интерфейс.
- **Почему выбран этот вариант:** Модель хорошо структурирует табличные артефакты QA по заданным ограничениям и точно учитывает схему эндпоинтов FastAPI. Промпт сформулирован с явным указанием роли QA-инженера, списка эндпоинтов и запретом на выдумывание несуществующих функций.
- **Полный промпт:**
  «Ты — QA-инженер. Изучи следующие требования к системе учёта заявок (Request System API на FastAPI + SQLite): эндпоинты GET/POST /requests, GET/PATCH/PUT/DELETE /requests/{id}, GET /users, GET /categories, GET /statuses, GET /health. Поля заявки: reg_number (REQ-XXX), theme (5–150 симв.), description (10–2000 симв.), priority (Низкий, Средний, Высокий, Критический), category_id (1–4), status_id (1–4), applicant_id, executor_id. Составь тест-кейсы с ID, предусловиями, шагами, входными данными, ожидаемым результатом и типом (позитивный, негативный, граничный, роли, интеграционный, API). Не придумывай функции, которых нет в требованиях. Отметь вопросы, которые нужно уточнить у разработчика».
- **Краткий результат:** Модель сгенерировала таблицу из 18 тест-кейсов и список из 3 уточняющих вопросов (поведение при дубликате reg_number, формат ответа при пустом PATCH, обработка несуществующих внешних ключей).
- **Что принято/отклонено:** Приняты 16 базовых сценариев CRUD и валидации. Отклонены 2 сценария проверки JWT-токенов (в нашем API нет авторизации по заголовку Authorization). По вопросам модели в код src/main.py были добавлены проверки внешних ключей (возврат 400 Bad Request) и запрет пустого тела PATCH.
- **Самостоятельная проверка:** Кейсы выполнены вручную через Swagger UI ([http://158.160.148.23:8000/docs](http://158.160.148.23:8000/docs)) и curl. Например, curl -i http://localhost:8000/requests/9999 вернул HTTP/1.1 404 Not Found и JSON {"status_code":404,"error":"Not Found","message":"Заявка с id=9999 не найдена","details":null} — ожидаемый результат подтвердился.
- **Вклад студента:** Доработал набор до 22 тест-кейсов в testing/lab9/test_cases.csv, прогнал все запросы на реальном стенде и проставил фактические результаты.

  «Предложи черновики автоматических тестов на pytest + FastAPI TestClient для модулей src/main.py и src/crud.py проекта Request System. Нужны минимум 3 теста бизнес-логики, 3 теста API (201, 400, 404), 2 теста валидации (422) и 2 регрессионных теста. Тесты не должны изменять рабочую БД SQLite».

## Запись 4 (ЛР №10 — Взаимодействие 2: Диагностика ошибки запуска и падения теста)
- **Дата и задача:** 09.11.2026. Анализ лога падения при запуске контейнера и сборке зависимостей (pydantic-core на Python 3.14 и Could not import module "src.main").
- **Модель:** Gemini (Google AI), веб-интерфейс.
- **Почему выбран этот вариант:** Модель позволяет быстро локализовать системные ошибки сборки Rust/PyO3 и конфликты прав доступа UID в Docker volumes.
- **Полный промпт:**
  «Объясни причину ошибки и предложи варианты диагностики: при локальной установке pip install -r requirements.txt падает сборка pydantic-core с ошибкой "the configured Python interpreter version (3.14) is newer than PyO3's maximum supported version (3.13)", а в Docker-контейнере с USER appuser и volume ./src:/app/src возникает "ERROR: Error loading ASGI app. Could not import module src.main"».
- **Краткий результат:** Модель объяснила несовместимость CPython 3.14 с PyO3 0.22 и указала на конфликт прав доступа (PermissionError) между UID пользователя внутри контейнера (appuser) и владельцем примонтированного каталога ./src на хосте.
- **Что принято/отклонено:** Принято решение запускать приложение и pytest внутри контейнера на базе стабильного образа python:3.12-slim с выдачей прав chmod -R 777 /app и установкой PYTHONPATH=/app.
- **Самостоятельная проверка:** После пересборки sudo docker-compose up -d --build контейнер перешёл в статус Up (healthy), а запуск pytest внутри контейнера прошёл без ошибок.
- **Вклад студента:** Исправил Dockerfile, docker-compose.yml, пересобрал окружение на сервере в Yandex Cloud и провёл финальную регрессию.
